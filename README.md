# نظام إدارة كفالة الأيتام — الجمعية الشرعية

تطبيق ويب داخلي متكامل لإدارة برنامج كفالة الأيتام: الأسر وأفرادها، الاستحقاق والعمر، المستندات، الكفلاء والتعهدات، التبرعات والمصروفات، كشوف الاستحقاق والصرف الشهري، الأرصدة والتسويات، والتقارير الشهرية القابلة للطباعة والتصدير والاعتماد.

- واجهة عربية بالكامل (RTL) بخط Cairo مضمَّن محليًا، متجاوبة مع الجوال والتابلت.
- كل الأرقام محسوبة من قاعدة البيانات الفعلية؛ لا توجد بيانات وهمية في الإنتاج.
- الصلاحيات مطبقة في الخادم على كل طلب، والسجلات المالية وسجل التدقيق محمية من التعديل والحذف على مستوى قاعدة البيانات.

---

## 1. التقنية المستخدمة

| الطبقة | التقنية |
|---|---|
| الخادم | Node.js 20+ و Express 4 (عرض من الخادم بقوالب EJS، بلا بناء واجهة منفصل) |
| قاعدة البيانات | PostgreSQL 14+ (ترحيلات SQL، قيود وفهارس ومشغلات حماية) |
| الجلسات | express-session مخزنة في PostgreSQL، كوكي HttpOnly و Secure في الإنتاج |
| كلمات المرور | bcrypt (12 جولة)، قفل الحساب بعد 5 محاولات، مصادقة ثنائية TOTP اختيارية |
| الحماية | Helmet (CSP صارم)، رموز CSRF، استعلامات مُعلَّمة ضد SQL Injection، ترميز تلقائي ضد XSS |
| الرسوم البيانية | Chart.js (مضمّن محليًا) |
| PDF | Chromium عبر puppeteer-core (تشكيل عربي صحيح، A4، أرقام صفحات) |
| Excel / CSV | ExcelJS (ورقة من اليمين لليسار) و CSV بترميز UTF-8 مع BOM |
| الاختبارات | node:test + supertest (46 اختبارًا آليًا) |

## 2. المتطلبات

- Node.js 20 أو أحدث، PostgreSQL 14 أو أحدث (مع أدوات `pg_dump` و `pg_restore` بنفس الإصدار).
- متصفح Chromium على الخادم لتصدير PDF وحفظ التقارير المعتمدة (الطباعة من المتصفح تعمل بدونه).

## 3. التثبيت والتشغيل

```bash
# 1) تنزيل الاعتماديات
npm ci

# 2) إنشاء قاعدة البيانات ومستخدمها (مرة واحدة)
sudo -u postgres psql -c "CREATE USER kafala_app WITH PASSWORD 'كلمة-قوية';"
sudo -u postgres psql -c "CREATE DATABASE kafala OWNER kafala_app;"

# 3) ملف الإعدادات
cp .env.example .env
#   - املأ DATABASE_URL و SESSION_SECRET و BACKUP_KEY و CHROME_PATH و STORAGE_DIR
#   - لتوليد مفتاح عشوائي:
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"

# 4) إنشاء الجداول (يُنفَّذ تلقائيًا أيضًا عند تشغيل الخادم)
npm run migrate

# 5) إنشاء حساب مدير النظام الأول (انظر القسم 4)
npm run create-admin

# 6) التشغيل
npm start          # الإنتاج
npm run dev        # التطوير مع إعادة التشغيل التلقائي
```

يعمل النظام على `http://localhost:3000`. في الإنتاج ضعه خلف Nginx مع HTTPS (القسم 12).

## 5. إعداد قاعدة البيانات

- الترحيلات في `db/migrations/*.sql` وتُطبق بالترتيب مرة واحدة (جدول `schema_migrations`).
- الجداول الأساسية: `users, roles, permissions, role_permissions, user_roles, families, guardians, family_members, documents, eligibility_reviews, eligibility_decisions, sponsors, family_sponsorships, sponsor_contributions, funds, donation_types, donations, expense_categories, expenses, expense_approvals, monthly_runs, monthly_entitlements, disbursements, ledger_entries, financial_adjustments, financial_periods, monthly_reports (+ عرض report_versions), audit_logs, notifications, import_batches, system_settings`.
- قيود الحماية المضمّنة:
  - `ledger_entries` و `audit_logs` و `eligibility_decisions`: يمنع التعديل والحذف (مشغلات).
  - التبرعات والمصروفات والصرف والاستحقاقات والتقارير: يمنع الحذف النهائي.
  - استحقاق واحد لكل أسرة لكل شهر، ولا يتجاوز المصروف المستحق (CHECK)، ومفتاح منع تكرار فريد لكل عملية صرف.
  - قيد مالي واحد فقط لكل مصدر (لا يُحتسب التبرع أو الصرف مرتين).
  - التقرير المعتمد لا يمكن تعديل أرقامه أو ملفه؛ أي تغيير = إصدار جديد.
- المبالغ مخزنة `NUMERIC(14,2)` وتُحسب بالقروش كأعداد صحيحة لتفادي أخطاء الكسور.

## 6. المستخدمون والصلاحيات

**المستخدمون والأدوار ← إضافة موظف**: اسم مستخدم لاتيني واسم كامل وأدوار. اترك كلمة المرور فارغة ليولد النظام كلمة مؤقتة قوية تظهر مرة واحدة؛ يُجبر الموظف على تغييرها عند أول دخول. لا يُطلب بريد إلكتروني.

الأدوار الجاهزة (قابلة للتخصيص من «تخصيص الصلاحيات»، ويمكن إنشاء أدوار جديدة):

| الدور | أبرز صلاحياته |
|---|---|
| مدير النظام | كل الصلاحيات، المستخدمون، الإعدادات |
| مدير الجمعية / مسؤول الكفالات | الأسر، قرارات الاستحقاق، اعتماد المستندات والمصروفات والصرف والتقارير |
| مسؤول البحث الاجتماعي | إضافة الأسر والأفراد وتحديثها ورفع المستندات والاستيراد (دون قرارات الاستحقاق) |
| المحاسب | التبرعات والتحصيل، المصروفات والدفع، الكشوف، التسويات، إعداد التقارير |
| أمين الصندوق | تسجيل الصرف الفعلي وإرفاق الإيصالات |
| المراجع | عرض السجلات والتقارير وسجل التدقيق دون أي تعديل |

- سحب الصلاحية يسري فورًا حتى على الجلسات المفتوحة.
- **فصل المهام** (من الإعدادات): لا يعتمد المستخدم مصروفًا أو صرفًا أو تقريرًا أنشأه بنفسه.
- النظام يمنع إزالة آخر مدير نظام نشط.
- يمكن للمدير إعادة تعيين كلمة مرور موظف، أو فك قفله، أو إلغاء مصادقته الثنائية عند فقدان الجوال.

## 7. تسجيل الأسر والكفلاء

**الأسر ← إضافة أسرة**: بيانات الأسرة، طريقة احتساب الكفالة (ثابت للأسرة / لكل مستفيد / مختلط)، بيانات ولي الأمر. رقم الملف (F-xxxx) يُنشأ تلقائيًا، ويُنبَّه عند تكرار رقم الجوال.
- الهوية وبيانات البنك والملاحظات السرية لا تظهر ولا تُعدَّل إلا بصلاحية «البيانات الحساسة»، ولا تُطبع في أي تقرير.
- **إضافة فرد**: الاسم وتاريخ الميلاد (العمر يُحسب تلقائيًا) والجنس والدراسة والمبلغ الفردي. إذا أضافه باحث اجتماعي تكون حالته «قيد المراجعة» حتى يعتمدها المسؤول.
- **إجراءات الاستحقاق** تحت كل فرد: قرار موثق (الحالة، السبب، تاريخ السريان)، أو تسجيل زواج للمستفيدة (ينشئ طلب مراجعة ولا يوقف الكفالة دون قرار).
- **المستندات**: PDF / JPG / PNG / WEBP، يُفحص محتوى الملف فعليًا (لا الامتداد فقط)، تُحفظ بأسماء عشوائية خارج المجلد العام، وتُعرض فقط بعد التحقق من الصلاحية، مع استبدال يحتفظ بالنسخة السابقة.
- **حالة الملف** (نشط/قيد المراجعة/موقوف/مغلق/مؤرشف) تتطلب سببًا ولا تحذف أي سجل صرف.

**قواعد العمر والاستحقاق** (قابلة للتعديل من الإعدادات): عند بلوغ الذكر سن المراجعة (18 افتراضيًا) دون إثبات جامعي معتمد ساري تتحول حالته تلقائيًا إلى «بانتظار إثبات الدراسة» بقرار آلي موثق. اعتماد إثبات جامعي ساري يعيده «مستحق بإثبات جامعي»، وانتهاء الإثبات يعيده لطلب التحديث. الإناث لا تتأثر بالعمر. تنبيهات قبل البلوغ بثلاثة أشهر وشهر، وقبل انتهاء الإثبات والمستندات. شاشة **مراجعة الاستحقاقات** تجمع كل ذلك.

**الكفلاء ← إضافة كفيل** ثم «ربط بأسرة» (كفيل لعدة أسر، وعدة كفلاء للأسرة). من **متابعة التعهدات الشهرية** أنشئ تعهدات الشهر، ثم سجّل التحصيل من صفحة الكفيل. التعهد لا يُحتسب مالًا حتى يُؤكَّد تحصيله، وتوقف الكفيل لا يوقف استحقاق الأسرة بل يظهرها في «أسر تحتاج كفيلًا».

## 8. التبرعات والمصروفات والصرف

- **التبرعات ← تسجيل تبرع**: النوع يحدد الصندوق (عام / مقيد لكفالة الأيتام / مخصص لأسرة / مساهمة كفيل). المحاسب يؤكد التحصيل فيُنشأ قيد مالي واحد. لا يقبل تكرار مرجع التحويل. الإلغاء بقيد عكسي موثق.
- **المصروفات**: مسودة ← إرسال للاعتماد ← اعتماد (شخص آخر) ← دفع (يُخصم من الصندوق). لا يُسمح بالصرف من الصندوق المقيد على تصنيفات لا تخصه، ولا بتجاوز الرصيد.
- **الأرصدة والتسويات**: سجّل الرصيد الافتتاحي لكل صندوق مرة واحدة، وأي تصحيح بتسوية موثقة. يمكن إقفال فترة مالية لمنع أي عملية بتاريخ داخلها.
- **الاستحقاقات والصرف الشهري**: اختر الشهر ← «إنشاء كشف الاستحقاقات». يُنشأ سجل لكل أسرة نشطة حسب طريقة احتسابها وحالات الاستحقاق المعتمدة، ويُرفض الكشف المكرر (إضافة الأسر غير المدرجة إجراء إداري منفصل). من شاشة المتابعة: «تسجيل الصرف» (كامل أو جزئي، مع الطريقة والمرجع والإيصال). كل نموذج يحمل مفتاحًا يمنع التسجيل المزدوج، ويُقفل السجل أثناء الحفظ لمنع الطلبات المتزامنة. فلتر «الأسر التي لم تستلم فقط» متاح.

## 9. التقرير الشهري وطباعته

**التقارير الشهرية**: اختر الشهر والسنة ونوع التقرير والمستوى (تفصيلي للمحاسب / مختصر للإدارة) ← «إنشاء التقرير» ← راجع الإجماليات ← **طباعة** (قالب A4 مخصص، رؤوس جداول متكررة، إجماليات، توقيعات) أو **PDF** أو **Excel** أو **CSV**.

التقارير: المالي الشهري، الكفلاء، الأسر، الصرف الشهري، المصروفات، مراجعة الاستحقاق. التقرير المالي يوضح طريقة احتساب كل رقم، ومساهمات الكفلاء تظهر كجزء من إجمالي التبرعات لا كإضافة عليه.

**الاعتماد**: «حفظ نسخة وإرسالها للاعتماد» يحفظ لقطة ثابتة من الأرقام وملف PDF مع ملاحظات المحاسب. يعتمدها شخص آخر، فيُنشأ PDF نهائي بختم «نسخة معتمدة» واسم المعد والمعتمد وتاريخ الاعتماد. إذا تغيرت البيانات بعد الإعداد يرفض النظام الاعتماد ويطلب إعادة الإعداد. أي نسخة جديدة لاحقًا تستبدل المعتمدة بسبب مكتوب، وتبقى السابقة محفوظة كما هي، ويُتحقق من سلامة ملف PDF ببصمة SHA-256 عند تنزيله.

## 10. استيراد البيانات

**استيراد البيانات**: نزّل القالب (الأسر / الأفراد / الكفلاء) ← املأه ← ارفع xlsx أو csv ← راجع مطابقة الأعمدة والمعاينة (أخطاء كل صف، التكرار داخل الملف ومع قاعدة البيانات) ← «تأكيد الاستيراد». تُستورد الصفوف الصالحة فقط، ويُحفظ تقرير بالمستورد والفاشل وأسبابه. الأسر المستوردة تبدأ «قيد المراجعة».

## 12. ما يحتاج إلى إعداد خارجي قبل التشغيل

1. خادم PostgreSQL وقاعدة بيانات ومستخدم بكلمة قوية.
2. متصفح Chromium على الخادم وضبط `CHROME_PATH` (لـ PDF والتقارير المعتمدة).
3. نطاق (Domain) وشهادة HTTPS (مثلًا Let's Encrypt).
4. قيم سرية جديدة: `SESSION_SECRET` و `BACKUP_KEY` (احفظ مفتاح النسخ خارج الخادم).
5. مساحة تخزين خارجية للنسخ الاحتياطية (قرص آخر أو تخزين سحابي).
6. من **الإعدادات**: اسم الجمعية وهاتفها وعنوانها وشعارها (الشعار الحالي مضمّن افتراضيًا) والعملة وقواعد الاستحقاق والمستندات الإلزامية.
7. **سياسة الاحتفاظ بالبيانات**: يجب أن تحددها إدارة الجمعية وفق الأنظمة المحلية؛ النظام يحتفظ بكل السجلات المالية ويدعم الأرشفة دون حذف.

## 13. النشر الآمن على الإنترنت

**خيار أ — Docker**
```bash
cp .env.example .env   # املأ القيم، وأضف DB_PASSWORD=...
docker compose up -d --build
docker compose exec app node scripts/create-admin.js
```
**خيار ب — خادم Linux مباشرة**: انسخ المشروع إلى `/opt/kafala`، أنشئ مستخدم نظام `kafala`، استخدم `deploy/kafala.service` (systemd) و `deploy/nginx-kafala.conf` (Nginx + HTTPS)، ثم `certbot --nginx`.

قائمة تحقق النشر:
- `NODE_ENV=production` (يفعّل الكوكي الآمن و HSTS، ويرفض المفتاح التجريبي).
- التطبيق يستمع على `127.0.0.1` فقط، و Nginx وحده مكشوف (المنفذان 80/443).
- جدار ناري يغلق منفذ PostgreSQL من الخارج.
- مجلد `STORAGE_DIR` خارج أي مجلد ويب، بصلاحيات للمستخدم `kafala` فقط.
- فعّل المصادقة الثنائية لكل الحسابات الإدارية والمالية.
- حدّث النظام والاعتماديات دوريًا (`npm audit`).

## 14. النسخ الاحتياطي والاستعادة

**النسخ**: `npm run backup` ينشئ ملفًا واحدًا مشفرًا (AES-256-GCM بمفتاح مشتق من `BACKUP_KEY`) يحتوي قاعدة البيانات كاملة والمستندات والتقارير المعتمدة والشعار، في `STORAGE_DIR/backups` أو المسار المحدد بـ `--out`.

جدولة يومية (crontab للمستخدم kafala) ثم نسخ الملف خارج الخادم:
```cron
30 2 * * * cd /opt/kafala && /usr/bin/node scripts/backup.js --out /var/backups/kafala >> /var/log/kafala-backup.log 2>&1
```

**الاستعادة** (تستبدل البيانات في القاعدة الهدف):
```bash
npm run restore -- /var/backups/kafala/kafala-2026-10-14-02-30.kbak --yes
# أو إلى قاعدة تجريبية للتحقق دون المساس بالإنتاج:
npm run restore -- ملف.kbak --yes --target-db postgres://.../kafala_restore_check --storage /tmp/check
```
**اختبر الاستعادة دوريًا** (مثلًا شهريًا) إلى قاعدة منفصلة وقارن أعداد الأسر ومجموع القيود — هذا ما يفعله الاختبار الآلي `05-backup-volume`.

## 15. النشر على Vercel + Neon (الطريقة المستخدمة حاليًا)

- الكود على GitHub (مستودع خاص)، و Vercel يبني وينشر تلقائيًا مع كل رفع، وقاعدة البيانات على Neon (PostgreSQL).
- الملفات (المستندات، التقارير المعتمدة، الشعار) تُخزن داخل قاعدة البيانات (جدول `stored_files`) لأن Vercel لا يحتفظ بالملفات على القرص؛ حد الملف 4 ميجابايت.
- الجداول تُنشأ تلقائيًا عند أول تشغيل، ومفتاح الجلسات يُولّد ويُحفظ في قاعدة البيانات إن لم يُضبط `SESSION_SECRET`.
- **التفعيل الأول**: ضع متغير البيئة `OWNER_SETUP_KEY` في Vercel، ثم افتح الموقع ← صفحة «تفعيل النظام» ← أدخل المفتاح وأنشئ حساب مدير النظام. الصفحة تتعطل نهائيًا بعد إنشاء أول حساب.
- PDF يعمل بنسخة Chromium المخصصة للاستضافة (`@sparticuz/chromium`).
- محرك الاستحقاق والتنبيهات يعمل تلقائيًا عند الاستخدام (كل 6 ساعات على الأكثر)، ويمكن إضافة `CRON_SECRET` لتفعيل التشغيل اليومي المجدول.
- **النسخ الاحتياطي**: سير عمل GitHub Actions اليومي (`.github/workflows/backup.yml`) يأخذ نسخة مشفرة ويحفظها 90 يومًا، بعد ضبط سرّي المستودع `BACKUP_DATABASE_URL` (رابط Neon المباشر) و `BACKUP_KEY`. الاستعادة بالأمر `npm run restore` كما في القسم 14، إضافة إلى ميزة الاستعادة لنقطة زمنية في Neon نفسه.
